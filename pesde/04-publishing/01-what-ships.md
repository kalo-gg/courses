# What ships: includes and the refusals

*The whitelist that decides what goes in the tarball, and the checks publish runs before it uploads anything.*

pesde · Publishing to the Registry · 10 min

---

Two fields decide whether a publish will work: `includes`, which lists what goes in the tarball, and `[target]`, which says what environment the package is for and what it exports.

**The publishable minimum**

```toml
includes = [
  "pesde.toml",
  "README.md",
  "LICENSE",
  "src/**/*.luau",
]

[target]
environment = "luau"
lib = "init.luau"
```

> **`includes` is a whitelist**
>
> Files and directories not listed are **not published**. The failure mode is quiet: the package installs, and then a require fails for everyone but you, because the file it needs was never in the tarball. `pesde publish --dry-run` produces the tarball without uploading it, which is how you check.

## What publishing flatly refuses

`pesde publish` runs a list of checks before it uploads anything, and most of them are hard failures rather than warnings. They are worth reading once, because several fire on things a Wally or Rojo user has sitting in their repository already.

The pattern behind the list is that publishing refuses anything it cannot honestly describe. A toolchain manifest or a `.git` directory in the tarball is somebody else's build set-up shipped as your package; a `default.project.json` is the consumer's file to generate, not yours to send; a Roblox target with no `build_files` describes nothing for their sync tool to mount; and a lockfile behind the manifest means the versions you tested are not the versions you are publishing — a check pesde runs only for `roblox` and `roblox_server` targets, because they are the ones whose dependencies end up inside the published tree. Every one of them is fixed in the manifest, not on the command line. `private = true` is the odd one out: it is not one of these refusals at all — publish prints `package is private, refusing to publish` to **stdout** and exits **0**, where every other refusal is an error, so a pipeline that only checks the exit code will think a private package published.

| It bails when | The message |
| --- | --- |
| `includes` matches a toolchain manifest — `rokit.toml`, `foreman.toml`, `aftman.toml` — or a `.DS_Store` | `forbidden file rokit.toml was included.` |
| `includes` matches a `default.project.json` | `default.project.json was included at …, this should be generated by the roblox_sync_config_generator script upon dependants installation` |
| `includes` matches the `.git` directory | `git directory was included, please remove it` |
| A Roblox target has no `build_files`, or names one that is missing or unpublished | `no build files found in target` · `build file src does not exist` · `build file src is not included, please add it` |
| The target exports no `lib`, `bin` or scripts | `no exports found in target` |
| A Roblox package has a non-dev dependency on a non-Roblox package | `roblox packages may not depend on non-roblox packages` |
| The lockfile is behind the manifest, **in a `roblox` or `roblox_server` target** | `outdated lockfile, please run the install command first` |

`private = true` stops earlier still, with `package is private, refusing to publish`.

> **Coming from Wally? Two of these will catch you**
>
> A broad `includes` glob sweeps up the `rokit.toml` your repository almost certainly has, and the message talks about toolchain managers rather than about your glob. And if your Roblox package depends on a Lune build script or test runner, that dependency **must** live in `[dev_dependencies]` — the non-Roblox check skips dev dependencies and nothing else. That constraint is the reason The Manifest's dev-dependency table matters for Roblox authors specifically.

**Checking before you publish**

```bash
pesde publish --dry-run   # builds the tarball, uploads nothing
```

**Key points**

- `includes` is a whitelist; what is not listed is not published.
- `pesde publish --dry-run` builds the tarball so you can look before uploading.
- Refusals: toolchain manifests, `.git`, `default.project.json`, a Roblox target without `build_files`, no exports, a non-Roblox runtime dependency in a Roblox package, and — for `roblox` and `roblox_server` targets only — a lockfile behind the manifest.
- `private = true` refuses too, but prints to stdout and exits 0; missing README and docs are only warnings — and show up on the registry page.
