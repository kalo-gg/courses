# 4. Publishing to the Registry

*A registry that never forgets — so the interesting part is what you do instead of deleting.*

pesde · Medium

---

Publishing is three commands, and it is permanent. What ships covers the includes whitelist and the checks publish runs before uploading; Authentication and scopes covers GitHub login, tokens per index and how a scope is owned and shared; Publishing it covers the dry run, the flags, multi-target releases and the docs the registry page shows; Yanking and deprecating covers the two levers that exist because deletion does not.

## Lessons

1. [What ships: includes and the refusals](01-what-ships.md) — The whitelist that decides what goes in the tarball, and the checks publish runs before it uploads anything.
2. [Authentication and scopes](02-auth-and-scopes.md) — Logging in through GitHub, keeping a token per index, and how a scope is owned, shared and transferred.
3. [Publishing it](03-publishing-it.md) — Dry run, publish, the flags, multi-target releases, and the docs the registry page shows.
4. [Yanking, deprecating and living with it](04-after.md) — The two levers that exist because deletion does not: yank a version, deprecate a package, and undo either.
