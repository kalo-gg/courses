# 7. Shipping Emberfall

*Test modes and storybooks, the diagnostics you alert on, the security line, and the layout the final project follows.*

Scribe · Hard

---

The last module is about shipping. Mode keeps a play-test away from real profiles and boards, and edit mode renders a storybook with no server anywhere. Diagnostics give every failure a stable code, a health status and counters, so you know what to alert on. The security line is exact: a client emits two frame types, Scribe proves the shape of every argument, and your handler proves the entitlement. The Architecture lesson lays Emberfall out in five places, and the final project builds all of them: the template with a migration, services, an admin path, diagnostics and a HUD, run end to end.

## Lessons

1. [Testing and edit mode](01-testing.md) — Mode closes off every store a play-test could touch; edit mode renders a storybook with no server anywhere.
2. [Diagnostics](02-diagnostics.md) — Stable log codes, a health status, per-player save state and counters: what to route where, and how to read them.
3. [The security line](03-security.md) — A client asks and the server decides; what Scribe checks before your code runs, and which decisions stay yours.
4. [Laying out Emberfall](04-architecture.md) — A shared module, server services, a client HUD, a diagnostics script and an admin path: the plan the final project follows.
