# Continuous integration

*The exit-code contract, two invocations, a workflow file, and the reporters that feed a pull request.*

Lest · The Loop and CI · 12 min

---

Lest is a single static binary with no runtime to install alongside it, so a CI job is mostly "get the binary, run `lest`". Everything interesting is in what the exit code means.

| Code | Meaning |
| --- | --- |
| `0` | Everything passed |
| `1` | **Test** failures |
| `2` | **Tool** error |

The line between 1 and 2 is deliberate. A test that times out, a spec that fails to load, a failing assertion, a `--min` shortfall, a committed `.only` under `--forbid-only` — those are **test failures**. The project ran and did not meet its own standard.

> **A tool error is not a test failure**
>
> A backend that could not start, a config that will not parse, a protocol line that will not decode, a suite that produced no outcomes, a coverage minimum with nothing in the table, a `--changed` ref that does not exist, a `lest` that selected no suites because every one of them is `default = false` — the run **did not happen**, and calling that a test failure would be a lie your dashboard then repeats.

**Branching on it**

```bash
lest --reporter junit > results.xml
case $? in
  0) echo "green" ;;
  1) echo "tests failed" ;;
  2) echo "Lest itself broke — do not report this as a test failure" >&2 ;;
esac
```

## A workable CI invocation

**Two invocations, deliberately**

```bash
lest --forbid-only --reporter junit > results.xml
lest run unit --coverage --coverage-format lcov --min 80 > lcov.info
```

`$CI` is already set by every mainstream provider, so `default = false` suites run in the first line without a flag — on every backend except `studio` and `gargantuan`, which stay by-name-only.

> **Why the coverage pass names a suite**
>
> Coverage is native-only, so the second line **narrows to the native suite on purpose**. Leave `run unit` off and the bare `lest` re-runs your `default = false` engine suite too — a fresh Open Cloud task *per spec file*, paid twice, to compute a number cloud cannot contribute to. One pass for the report, one narrowed pass for the tracefile.

| Flag | What it buys |
| --- | --- |
| `--forbid-only` | A committed focus silences its file; make it exit 1 instead of passing quietly |
| `--reporter junit` | Inline test annotations on the pull request |
| `--min` | A coverage regression fails the build |
| `$CI` | The engine suite runs here and nowhere else, with no flag to remember |
| `--changed origin/main` | On a large repository, run only what the branch could have broken |

`--reporter pretty` is the default; `json` prints one object per line for tooling, and `junit` writes the XML that CI providers turn into annotations. Color is disabled automatically when the output is not a terminal or `NO_COLOR` is set, and `--no-color` forces it off, so a redirected report never contains escape codes.

> **`--changed` needs the ref to actually exist**
>
> A git repository and a **valid ref**, or it is a tool error — exit 2, the "Lest broke" code, for what is really a checkout problem. And this is the common way to hit it: most CI providers **shallow-clone by default**, which leaves `origin/main` missing on the runner. Fetch the history first.

**GitHub Actions**

```text
- uses: actions/checkout@v4
  with:
    fetch-depth: 0     # so --changed can see the base ref

- name: Test
  run: lest --reporter junit > results.xml
  env:
    ROBLOX_API_KEY: ${{ secrets.ROBLOX_API_KEY }}
```

The API key is a secret and comes from the secret store; the universe and place ids are not, and stay in `lest.toml`.

**Key points**

- 0 passed, 1 tests failed, 2 the tool could not run them — never conflated.
- One pass for the report with `--forbid-only --reporter junit`; one narrowed native pass for coverage.
- `--changed` needs a real ref: `fetch-depth: 0`.
- The key comes from the secret store; the ids stay in `lest.toml`.
- `json` and `junit` reporters feed tooling; color turns itself off when redirected.
