# Rules

*Every transformation is off until you name it, and three of them share one footgun.*

Larvae · Builds & Profiles · 10 min

---

A rule is a transformation applied while processing. There are two families: larvae's own, and the darklua parity set carrying darklua's names so an existing pipeline moves across without relearning it. **All of them are off unless `[rules]` names them.**

**larvae's own**

```toml
[rules]
const_requires = true        # local X = require(...) becomes const X
use_get_service = true       # game.Players becomes game:GetService("Players")
dedupe_requires = true       # two top-level requires of one module become one
freeze_module = true         # table.freeze on a returned literal, when nothing writes to it
add_luau_directive = "strict"  # writes --!strict; an explicit one in the source wins
inject_module_path = "MODULE_PATH"  # a constant holding this file's path
```

Two of those are worth pausing on. `freeze_module` only freezes when nothing writes to the table, so it cannot break a module that mutates its own exports. And `add_luau_directive` yields to an explicit directive already in the file — the rule fills gaps rather than overriding intent.

## Options, and a footgun

**Rules that take options**

```toml
[rules]
remove_comments = { except = ["^--!", "^-- Copyright"] }

remove_calls = { functions = ["print", "warn"], preserve_arguments_side_effects = true }

# the same table, and the same footgun
remove_assertions = { preserve_arguments_side_effects = true }
remove_debug_profiling = { preserve_arguments_side_effects = true }

append_text_comment = { text = "generated by larvae, do not edit", location = "start" }
```

`preserve_arguments_side_effects` keeps the arguments evaluated when the call is removed — dropping `print(spend())` should not stop the spending. **Three** rules take that table, not one: `assert(spend())` and `debug.profilebegin(name())` are the same shape. `larvae.example.toml` shows the other two as a bare `= true`, which is where the impression that only `remove_calls` has the option comes from.

## The darklua set

The darklua parity set carries darklua's own names — `compute_expression`, `convert_index_to_field`, `remove_unused_variable`, `filter_after_early_return` and the rest — so an existing pipeline moves across without relearning it. Three moved and say so by name when you write them: `convert_require` points you at `[requires]`, `inject_global_value` at `[defines]`, and `remove_spaces` at `generator = "dense"`. The downlevelling rules are in the set too, and off.

> **Downlevelling is off for a reason**
>
> `remove_types`, `remove_compound_assignment`, `remove_continue` and friends exist for runtimes older than Luau, and they are all off by default. Each one makes the output less like the source, which is the opposite of what a Roblox project wants — a stack trace is easier to read when the shipped code still resembles what was written.

**Key points**

- Every rule is off until `[rules]` names it; larvae's own nine and the darklua set under darklua's names.
- `freeze_module` only freezes what nothing writes to; `add_luau_directive` yields to a directive already in the file.
- `remove_calls`, `remove_assertions` and `remove_debug_profiling` all take `preserve_arguments_side_effects` — `print(spend())` must still spend.
- `convert_require`, `inject_global_value` and `remove_spaces` moved to `[requires]`, `[defines]` and `generator = "dense"`.
- Downlevelling rules make the output less like the source; leave them off for Roblox.
