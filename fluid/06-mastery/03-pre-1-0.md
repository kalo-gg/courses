# Shipping on a release candidate

*Living with a library whose 0.7 line has never been tagged, and the toolchain around it.*

Fluid · Mastery & Migration · 10 min

---

Fluid's 0.7 line has no git tag and no GitHub release. `wally.toml` is the only version marker there is, and it says `0.7.0-rc.7`. The latest tagged **stable** release is v0.6.5, from 9 July 2026, and it is a different library in places. Knowing which one you have is not pedantry here; it is the first debugging step.

| Question | Where the answer is | Caveat |
| --- | --- | --- |
| Which version is this? | `wally.toml` in the repository | The tags stop at v0.6.5 |
| What changed? | `CHANGELOG.md`, Keep a Changelog format | 0.7.0's section is one line: "Removed dev groups" |
| What *really* changed? | The git log for the RC line | It also removed the action priority system and rewrote the graph and `bind` several times |
| What does the API look like? | `src/init.luau` — every export in one file | The README is ahead of the code in at least one place (`_G.__DEV__`) |
| Which version am I resolving? | `wally.lock` after `wally install` | A bare `@0.7.0-rc.7` is a range and will drift |

> **For this version, the changelog is not the whole story**
>
> `CHANGELOG.md`'s `0.7.0` section is a single line: "Removed dev groups". The commit log for the same RC line is longer, and includes at least one removal the changelog never mentions — the action priority system, deleted with the note that it "doesn't do anything and it seems to have never done anything ever" — plus several rewrites of the reactive graph and of `bind`, one of them reverted. On a pre-1.0 line, read the log as well.

## The toolchain around it

| Tool | Role | Version | Install |
| --- | --- | --- | --- |
| Wally | Package manager; writes `Packages/` | 0.3.2 | `rokit add UpliftGames/wally` |
| Rojo | Syncs source files into Studio | 7.7.0 | `rokit add rojo-rbx/rojo` |
| Rokit | Toolchain manager; pins the two above per project | 1.2.0 | `curl -sSf …/rokit/main/scripts/install.sh \| bash` |
| luau-lsp | Language server; reads Rojo's sourcemap | 1.69.0 | `rokit add JohnnyMorganz/luau-lsp` |

Fluid ships no CLI of its own, so its whole toolchain is the ordinary Roblox one. Pin all of it in `rokit.toml` for the same reason you pin Fluid.

Two manifests, two jobs. `rokit.toml` pins the binaries a fresh clone needs before it can build anything at all; `wally.toml` pins the libraries the built place will contain. Both are committed, both name exact versions, and neither of them is generated — `Packages/` is.

**rokit.toml**

```toml
[tools]
rojo = "rojo-rbx/rojo@7.7.0"
wally = "UpliftGames/wally@0.3.2"
luau-lsp = "JohnnyMorganz/luau-lsp@1.69.0"
```

`rokit install` puts these three on the path at exactly these versions, per project.

**wally.toml**

```toml
[dependencies]
fluid = "ffrostfall/fluid@=0.7.0-rc.7"
```

One habit across both files: exact versions, committed. `rokit install` and `wally install` then reproduce the build on any clone.

When a name does move — and on a pre-1.0 line it will — the cheapest defense is a thin module of your own that re-exports what you use. One file to fix, one place to read the diff, and the rest of your screen untouched. `Packages/fluid.luau` in the projects is the smallest version of that idea.

**Key points**

- The 0.7 line has no tag: `wally.toml` is the version, and the latest tagged stable release is v0.6.5.
- The changelog is one line for 0.7.0; the git log is the real record.
- `src/init.luau` lists every export in one file — it is the fastest way to check an API against your revision.
- Pin the toolchain in `rokit.toml` and the library in `wally.toml`, both exactly, both committed.
- A one-file re-export module gives you a single place to absorb a rename.
