# 8. Best Practices & Capstone

*Design components like a database, keep systems fast and testable, plan the server, then build it.*

JECS · Hard

---

The final module turns everything into habits: how the JECS author recommends designing components, a performance checklist grounded in how archetypes work, how to test world logic outside Roblox, and an architecture lesson that plans the wave-survival server file by file. The final project then assembles it from the two earlier projects' modules and downloads as a Roblox place.

## Lessons

1. [Designing components](01-designing-components.md) — Small, data-only components; tags vs fields; singletons; naming; and when a relationship is worth it.
2. [The performance checklist](02-performance-checklist.md) — What is cheap, what moves entities, and how to measure before optimizing.
3. [Testing outside Roblox](03-testing-outside-roblox.md) — Because JECS is pure Luau, world logic can be tested from the command line.
4. [Planning the wave-survival server](04-architecture.md) — Lay out the final project file by file: what goes where, which system runs before which, and how systems talk.
