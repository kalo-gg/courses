# From Luau to Alloy

*Rename a Luau file to `.aly` and let the lints show you, one warning at a time, what to rewrite.*

Alloy · The toolchain and mastery · 11 min

---

You have a working Luau codebase and want to move it to Alloy. You don't need a rewrite. Every Luau file is already an Alloy file, so you can rename `coin.luau` to `coin.aly` and it compiles. What changes is what the toolchain says about it. The lints know each Luau habit that has an Alloy form, and each one names the line and the form to use.

## The lints are the migration guide

**coin.aly, straight from Luau**

```luau
local Coin = {}
Coin.__index = Coin                      -- manual_class

function Coin.new(value: number)
  local self = setmetatable({}, Coin)
  self.value = value
  return self
end

function Coin:label(): string
  return 'Coin worth ' .. self.value     -- concat_interpolation
end

local coins = { Coin.new(1), Coin.new(5) } -- prefer_new, prefer_const
for _, coin in ipairs(coins) do          -- legacy_iterator
  print(coin:label())
end
```

This file compiles and runs as it is. The comments mark the lints v0.1.0 reports. None of them stops the build: a lint is advice, not an error.

| Lint | Reports | Write instead | `--fix` |
| --- | --- | --- | --- |
| `manual_class` | `X.__index = X` | `struct` and `impl` | No |
| `prefer_new` | `Coin.new(1)`, `Vector3.new(…)` | `new Coin(1)`, `new Vector3(…)` | Yes |
| `concat_interpolation` | `'Coin worth ' .. v` | `` `Coin worth {v}` `` | Yes |
| `legacy_iterator` | `ipairs(t)`, `pairs(t)` in a `for` | `for _, v in t do` | No |
| `raw_require` | `require(script.Parent.Shop)` | `import { x } from './Shop'` | No |
| `prefer_const` | a `local` nothing reassigns | `const` | Yes |

The `--fix` column is whether the lint carries a rewrite that keeps the program the same. `alloy lint --fix` and `alloy flux --fix` apply those; the rest are yours to make.

The lints sit in eight groups: **correctness**, **suspicious**, **style**, **complexity**, **perf**, **roblox**, **pedantic** and **naming**. Each lint is `allow`, `warn` or `deny`. A denied lint makes `alloy check` exit with 1, but no lint ever stops `alloy build`. Set the starting levels in `[lint]`, and give a lint or a whole group its own level in `[lint.rules]`. A lint's own entry beats its group's.

**alloy.toml**

```toml
[lint]
recommended = true      # every lint at the level it declares
strict = true           # the pedantic group, at warn

[lint.rules]
correctness = "deny"    # a whole group
raw_require = "allow"   # one lint, which beats its group
```

`alloy init` writes `recommended` and `strict` both on. With `recommended = false`, every lint starts at `allow` and `[lint.rules]` alone says what runs.

Four commands read the code. `alloy check` compiles every file, writes nothing, and reports the diagnostics and the lints. `alloy lint` runs the lints alone. `alloy flux` does what `check` does and adds the luau-lsp type check, with its errors mapped back onto your Alloy lines. `alloy fmt` lays the files out, and `--check` fails when a file would change.

## When a lint is wrong

**Three ways to quiet a lint**

```alloy
--@alloy-lint raw_require=allow
const Legacy = require(script.Parent.Legacy)

@allow(prefer_new)
const origin = Vector3.new(0, 10, 0)

--@alloy-ignore generated by the map tool
local spawn_at = Vector3.new(0, 5, 0)
```

`--@alloy-lint` sets a level for this file. `@allow` covers the declaration it sits on and moves with it. `--@alloy-ignore` silences everything on the next line with code. Text after the directive is the reason.

> **A directive or `@allow`?**
>
> Use `@allow(lint)` when one lint is wrong about one declaration. Use a directive when what you want to quiet isn't one declaration, or isn't a lint: a line the type checker misreads, a region (`--@alloy-ignore-start` and `-end`), the whole file (`--@alloy-nocheck`), or an error you mean (`--@alloy-expect-error`). `--@alloy-preserve` keeps `--fix` off the next line, but the lint still reports. Any other `--@alloy-` name is a `DirectiveError`.

**Key points**

- Every Luau file compiles as Alloy. The lints name each habit that has an Alloy form, on its line.
- Lints sit in eight groups at `allow`, `warn` or `deny`. A lint's entry in `[lint.rules]` beats its group's, and no lint stops a build.
- `check` compiles and lints. `flux` adds the type check. `lint` runs the lints alone, and `fmt` lays the files out.
- `--fix` applies only rewrites that keep the program the same. Structural changes such as `manual_class` are yours.
- Use `@allow` for one declaration. Use a `--@alloy-` directive for a line, a region, a file or an error.
